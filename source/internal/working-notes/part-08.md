# 8. Promotion rules

An item leaves Working Notes when one of four things happens.

## Promote to Framework Working State

Do this when:

- its dependency chain is clear;
- later reasoning should be allowed to assume it;
- its status can be stated precisely;
- important guardrails are known.

## Promote to a framework document

Do this when:

- the result is settled enough to explain to a reader;
- it belongs structurally in one of the maintained documents;
- the explanation will not distort the document's role.

The four maintained Substack framework documents are currently:

1. **A Universe Made of Logic**
2. **The Possibility Lane**
3. **Where the Framework Currently Stands**
4. **The Index of the Framework**

## Promote to Short Notes — the queue

Do this when the result has a standalone question/mechanism that could become a post.

The publication queue should not be used as reasoning memory.

## Archive / drop

Do this when:

- the branch fails;
- its useful lesson has been extracted;
- keeping the full branch active would create source noise.

Preserve enough history to prevent accidental resurrection, but do not keep a dead mechanism in the active reasoning path.

# 10. Maintenance rule

Current revision: `R20260820-1527-01` (2026-08-20 15:27 +07:00).


When a conversation produces something new, ask in this order:

1. **Is it already derivable enough that later reasoning may depend on it?**  
   Put it in **Framework Working State**.

2. **Is it interesting but still missing a step?**  
   Put it here, with a label and the exact pending or unresolved point.

3. **Is it a reader-facing correction or settled framework result?**  
   Update the corresponding maintained framework document and the status page.

4. **Is it a standalone publishable idea?**  
   Put it in **Short Notes — the queue**.

5. **Did it fail?**  
   Record the lesson briefly, then remove the dead mechanism from active ground.

> **Working Notes should preserve unresolved value without granting unresolved material authority.**
