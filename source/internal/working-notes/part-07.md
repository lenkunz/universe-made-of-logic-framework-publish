Actual erasure requires a stronger condition.

If the host structure carrying the distinctions is damaged or reorganised enough that those distinctions are no longer preserved, then later reconstruction cannot guarantee recovery of the original relation.

So:

> **Dormant is not erased, and inaccessible is not necessarily dormant for the same reason.**

The mechanism of failed access must be identified.

### Relative grain of old memory

A further personal observation is that older childhood memories can retain timeline and event structure while appearing less vivid in colour and sensory rendering than present experience.

Candidate:

`old memory seated under earlier ground`
→ `present ground resolves more finely`
→ `old constraint remains`
→ `old constraint is increasingly coarse relative to the present resolver`

This yields:

> **The memory may not have faded absolutely. The present may have become finer relative to it.**

This is not yet active ground.

It competes with ordinary explanations including encoding differences, interference, reconstruction, rehearsal, developmental change, and the influence of old photographic media / technology.

### Useful introspective split

When thinking about memories at different ages, record three variables separately:

- **access cost** — how difficult it is to reach the memory;
- **structural recovery** — how much event order, relation, place, people, and causal structure can be reconstructed;
- **rendering vividness** — colour, sensory sharpness, exact wording, and experiential detail.

The framework becomes more interesting only if these can dissociate.

If deliberate search improves all three together, a simple routing account may be enough.

If search restores structure strongly while vividness remains systematically coarse, the relative-grain hypothesis becomes more specific.

Neither outcome proves the framework, but each constrains what the memory branch is allowed to claim.

# 5. Framework-native system design

**APPLICATION**

This section is intentionally outside the framework. It asks what a system built according to the framework's economy might look like.

## 5.1 Learning as splitting

Resolution is the splitting of previously equivalent possibilities.

A framework-native learner could therefore begin with broad equivalence classes and split a class only when treating two cases as the same becomes consequentially wrong.

Possible architecture:

`coarse class`
→ `prediction / discharge`
→ `failure to seat cleanly`
→ `identify the local distinction that mattered`
→ `split only there`

The hoped-for economy is:

> **Splits are expensive. Lumping stays free until it fails.**

This resembles several existing learning ideas structurally, but resemblance is not validation.

### Open joint

**What signals that a class was wrongly lumped?**

A candidate answer is a claim that fails to seat. The gap would identify where a distinction must be introduced.

If that can be made local, it may reduce the need for global credit assignment.

Untested. This is the central difficulty, not a solved feature.

## 5.2 Deliberation, action, and practice as one cost gradient

**APPLICATION**

Possible interpretation:

- **Deliberation** — paying to seat a claim not yet available as stable structure.
- **Action / reaction** — discharge through structure already seated.
- **Practice** — converting repeatedly expensive resolution into cheap reusable path.

This would give a fast/slow behavioural split without requiring two fundamentally different architectures.

The same path could be deliberate when new and automatic after sufficient seating.

This application is conceptually close to active framework deductions about action/reaction and practice, but an implementation is not derived merely because the vocabulary fits.

## 5.3 Retrieval as descent through seated relations

**APPLICATION / UNSETTLED**

Possible design intuition:

Past traversal changes which later relations are cheap. Retrieval could therefore be implemented as movement toward increasingly compatible / lower-cost seated structure rather than exhaustive search.

The useful question is not whether this resembles an existing energy landscape. It does.

The unresolved question is whether the framework gives a principled way to construct that landscape from actual seating history rather than hand-designing it.

## 5.4 What does not disappear in an implementation

**APPLICATION / GUARDRAIL**

Two difficulties survive any architecture built from the framework.

### Seed direction

A loop cannot derive its first direction from nothing. Some anchor, criterion, or externally installed consequence must exist.

Do not pretend the framework removes the reward/aim problem. At best it explains why some seed is unavoidable and how later structure can become cheaper once established.

### Compatibility

Combining coarse structure from different sources still requires a criterion for when their constraints can share seating and when they cannot.

This is the same unresolved compatibility problem seen elsewhere, arriving in an engineering form.

# 6. Method notes

## 6.1 Visualisation can force a useful distinction

**METHOD**

Some deductions became clear only after the relation was represented visually.

## 6.2 Tools fail by importing familiar ontology

**METHOD**

Different tools are useful for different jobs, but one failure repeats across them:

> fluent output quietly restores familiar assumptions that the framework explicitly removed.

Examples include treating time as primitive, treating coarse as blurry, treating atoms as fixed primitive inventory, treating gravity as a force, or turning an aim into an already-resolved route.

The practical rule is:

1. use tools for synthesis, drafting, research, visualisation, or formatting;
2. check every generated explanation against the primitive dependency chain;
3. reject wording that changes a primitive even if the result sounds scientifically familiar.
