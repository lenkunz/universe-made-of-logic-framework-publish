# Memory Privacy and Scope

Updated: 2026-08-23
Status: CONTINUITY POLICY / NOT FRAMEWORK GROUND

The repository is currently **private**.

Therefore the `memory/` layer may preserve richer project-conversation continuity than would be appropriate in a public repository, including personal-origin intuitions when they directly shaped framework reasoning.

This supersedes the conservative public-repository warning written into the first revision of `memory/README.md`.

## Still do not store

Even in a private repository, do not place credentials, passwords, access tokens, private account identifiers, or unrelated sensitive records into framework memory.

## Appropriate memory content

- framework-native terminology and semantic guardrails;
- active reasoning frontier;
- deductions discovered conversationally but not obvious from final prose;
- why earlier framings were rejected or narrowed;
- personal metaphysical / introspective origin notes that are intentionally part of this project's reasoning history;
- publication and source-sync workflow;
- conversation migration context needed to continue without a giant handoff prompt.

## Authority guardrail

Personal or conversational memory can explain how a deduction arose, but it cannot override the current canonical source unless the user explicitly corrects the source in a later discussion.
