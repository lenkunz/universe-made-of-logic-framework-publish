# System Skill Graph, Ranking, and Branching

> **Status:** Speculative idea / non-canonical  
> **Scope:** System-world playground  
> **Do not treat this file as framework ground unless explicitly promoted later.**

## Core idea

The System should not have a finite pre-authored skill tree.

Humanity keeps creating new relations.

The System learns from those relations.

New materials, tools, cultures, discoveries, hobbies, technologies, environments, and combinations can make skills possible that were not previously recognizable.

Therefore:

> **The skill structure is an open-ended relation graph, not a completed tree.**

The System does not know every future branch.

---

# Rank measures maturity, not the end of possibility

A skill rank should answer something like:

> **How established is this person's current relation to this skill?**

It should not mean:

> "How close is this person to finishing this entire domain forever?"

A short coarse ladder is enough, for example:

> E -> D -> C -> B -> A -> S

The exact labels can still be adjusted later.

The important rule is:

> **S is not the final possible power state.**

It is a coarse recognition that the relation has become highly established.

At high maturity, growth often becomes more interesting sideways than upward.

---

## S can become ground for new relations

Example:

> Skill A: S  
> Skill B: A

A stable relation between them may create:

> New Skill C: C

The new skill does not automatically inherit the parents' ranks.

Being highly developed in A and B does not mean the person has already mastered using A and B together as one consequential relation.

Example:

> Blade Timing: S  
> Heat Control: A  
> Ingredient Timing: B

A new recognized composition might appear:

> Thermal Rhythm: C

That C is not an insult.

It represents a new relation that has only recently become stable enough to recognize.

---

# Branching replaces rank inflation

The world does not need:

> S  
> SS  
> SSS  
> EX  
> L  
> G  
> Divine  
> Transcendent  
> Transcendent II

until the alphabet collapses from exhaustion.

The space beyond a mature skill can instead grow through:

- specialization,
- branching,
- composition,
- teaching,
- adaptation,
- environmental variants,
- new materials,
- new tools,
- new participants,
- new social roles,
- newly recognized relations.

A mature skill can become ground for many later skills.

---

# Rankings solve a different problem

Personal skill rank and competitive standing should remain separate.

**Skill rank asks:**

> How mature is this relation for this person?

**Leaderboard asks:**

> How does this person's current performance compare with other participants in this recognized relation?

Therefore both of these can be valid:

> Sword Timing: S  
> World Sword Timing: Top 5,000

and:

> Thermal Rhythm: C  
> World Thermal Rhythm: Top 10

The second skill may be new enough that only a small group has developed it meaningfully.

This prevents "S rank" from becoming synonymous with "one of the ten strongest people alive."

---

# Rankings remain useful

Competition still needs coarse relative measurement.

Possible leaderboard bands include:

- Top 10,
- Top 100,
- Top 1,000,
- Top 5,000,
- Top 10,000,
- Top 50,000,
- Top 100,000.

Scopes can include:

- local,
- city,
- country,
- world,
- cross-domain.

The System should avoid fake precision unless the competition actually requires it.

"Rank 4,283.716" is usually nonsense.

---

# The System can estimate nearby branches

The System may recognize that some currently known relations are unusually compatible.

It can show things such as:

> **[Branch compatibility detected.]**  
> Current skill structure appears compatible with several relations involving controlled heat.  
> Strongest unresolved connection: timing under thermal transformation.  
> Exact resulting skill: unresolved.

This is not a recipe.

It does not say:

> Swordsmanship S + Cooking A + Fire Control B = Flame Chef Knight.

The route still belongs to experimentation and resolution.

Different people can begin with similar skills and produce different later branches because their history, environment, interest, embodiment, and use are different.

---

## Example

One person has:

> Knife Handling: S  
> Ingredient Reading: A  
> Heat Control: A  
> Movement: B

The System may recognize:

> Knife Handling <-> Ingredient Reading: Strong  
> Heat Control <-> Timing: Strong  
> Movement <-> Knife Handling <-> Heat Control: Unresolved but notable

After long restaurant work, this person may establish:

> Flow Kitchen: C

Another person with similar skills and combat history may instead establish:

> Heated Edge Rhythm: D

Same nearby structure.

Different realized relation.

---

# The System does not know every branch

This is a hard limit of the idea.

The System cannot truthfully display:

> **These are all possible evolutions of your skill.**

A better statement is:

> **[Three currently recognizable development routes detected.]**  
> Additional relations may become available through new experience, participants, materials, environments, or unresolved combinations.

The System only sees what has enough existing relation to become recognizable.

---

# New human discovery changes the graph

Suppose the System already recognizes:

- Cooking,
- Material Analysis,
- Heat Control.

Then humanity invents a new class of programmable matter.

Now entirely new relations can become possible:

- Cooking x Programmable Matter,
- Heat Control x Programmable Matter,
- Material Analysis x Programmable Matter.

These were not merely hidden menu options waiting in a database.

The required relation did not exist in the same way before.

A newly established skill can then become available as ground for further combinations.

The graph keeps changing.

---

# Humanity teaches the System possibility

A recurring cycle is:

> human interest  
> -> experimentation  
> -> repeated relation  
> -> resonance  
> -> reusable pattern  
> -> System recognition  
> -> wider access  
> -> variants  
> -> combinations  
> -> new relation

The System learns humanity.

Humanity changes what there is to learn.

This feedback loop prevents the skill space from closing.

---

# "Impossible" should be used carefully

Suppose someone asks:

> "Can Sword Timing combine with Fermentation?"

The System should not casually answer:

> **[Impossible.]**

A better response may be:

> **[No established relation recognized.]**

Someone may then spend six years doing something ridiculous and eventually establish the missing relation.

At that point:

> **[New reusable relation recognized.]**

The System's previous answer was still correct.

It said no established route was known, not that reality had been completely enumerated.

---

# Hobbies remain consequential

Because branching can happen across distant-looking relations, hobbies should not be dismissed as useless.

Examples:

> Competitive Gaming: A  
> Cooking: B  
> Team Coordination: S

may later contribute to:

> Multi-station Resource Timing

which may become useful in:

- kitchens,
- factories,
- dungeon teams,
- rescue work,
- event logistics,
- distributed crafting.

A relation that appears useless in one context can become strong ground somewhere else.

---

# Diversity pressure

A dense modern civilization can make famous paths extremely crowded.

If the only reward is "become better at the thing everyone already values," diversity collapses.

Branching creates another route.

A million people may pursue Swordsmanship.

Someone else creates:

> Swordsmanship x Dance x Spatial Memory

Another person later connects that with architecture.

Another connects it with dungeon mapping.

The graph can grow faster than everyone can converge on one global meta.

This supports a world where many meaningful specializations can coexist.

---

# What the System should show

The System should keep branch display coarse.

It should not dump millions of possible combinations onto a status screen.

A useful display may contain only a few nearby relations:

> **Likely development:** Heat Timing  
> **Possible composition:** Cooking x Material Analysis  
> **Unusual unresolved relation:** Cooking x Spatial Mapping

These are not the only possibilities.

They are the possibilities currently recognizable enough to be useful to this person.

---

# Skill relation graph

"Skill tree" is convenient slang, but "Skill Relation Graph" or "Skill Map" is more accurate.

A tree implies:

- a root,
- fixed branches,
- pre-authored destinations,
- complete knowledge of the structure.

This system instead has:

- multiple origins,
- loops,
- independent rediscovery,
- mergers,
- divergence,
- culture-specific branches,
- environmental branches,
- newly invented nodes,
- relations not yet recognizable.

No one, including the System, sees the complete graph.

---

## Working principle

> **Vertical rank measures maturity. Horizontal branching opens new possibility. Composition creates new skill relations. Competition measures relative standing inside a recognized branch. The graph remains open because new relations can continue to appear.**
